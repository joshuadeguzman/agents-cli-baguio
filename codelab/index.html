DevFest Baguio 2026 Build a root cause agent with Agents CLI Live demo

    About 45 minutes. Bonus: 25 more. Deploy: 15 more.

    Overview

    You will build a root cause agent. It reads a log file from a service that broke, finds the failure, and tells you why in plain words.

    The agent runs on your laptop. It uses ADK, Google's open source framework for agents, and Agents CLI, which creates, runs and evaluates ADK projects for you.

    What you'll build

    • An ADK agent with two tools: read_log and find_errors.
    • A log file with one planted failure for it to find.
    • A small eval dataset that checks the agent finds it.

    Words you'll see

    AgentA model, an instruction and some tools, in a loop. It decides which tool to call, reads the result, and answers.
    ToolA Python function the model can decide to call, like read_log.
    ADKAgent Development Kit: Google's open source framework for writing agents in code.
    Agents CLIA command-line tool that creates, runs, evaluates and deploys ADK projects.
    SkillA markdown file that teaches a coding agent how to use Agents CLI and the current ADK API.
    PlaygroundA local web chat for your agent that shows every step it takes.
    EvalTest prompts plus scoring rules, so you know the agent still works after a change.

    The same pattern runs in production. Color Health's assistant, built with ADK, checks if a woman is due for a mammogram and books the appointment (Google Cloud blog).

    What you'll learn

    • How to install Agents CLI and its skills.
    • How a Python function becomes a tool, and why the docstring matters.
    • How to watch tool calls in the ADK playground.
    • How to ask a coding agent to do the same work, and what to check after.
    • How to evaluate an agent with agents-cli eval run.

    Add two tools: read_log and find_errors

    In ADK, a tool is a plain Python function. You list it in the agent's tools, and the model can call it.

    The docstring is what the model reads. ADK sends the function name, the argument types and the docstring to the model. The model never sees your function body. A vague docstring means the model calls the tool at the wrong time, or not at all.

    Replace everything in app/agent.py with this:

    from pathlib import Path

from google.adk.agents import Agent
from google.adk.apps import App
from google.adk.models import Gemini
from google.genai import types

MODEL = "gemini-3.8-flash"

# sample_logs/ sits next to the app/ folder.
LOG_DIR = Path(__file__).resolve().parent.parent / "sample_logs"


def _log_path(file_name: str) -> Path | None:
    """Return the path for a file inside sample_logs/, or None."""
    path = (LOG_DIR / file_name).resolve()
    if path.parent != LOG_DIR.resolve() or not path.is_file():
        return None
    return path


def read_log(file_name: str) -> dict:
    """Read a whole log file from the sample_logs folder.

    Use this when you need the full context around an error, such as the
    config values printed at startup or what happened before a failure.

    Args:
        file_name: The log file name, for example "order-api.log".

    Returns:
        A dict with "status" and either "content" or "error_message".
    """
    path = _log_path(file_name)
    if path is None:
        available = sorted(p.name for p in LOG_DIR.glob("*.log"))
        return {
            "status": "error",
            "error_message": f"No log named {file_name!r}. Available: {available}",
        }
    return {"status": "success", "content": path.read_text()}


def find_errors(file_name: str) -> dict:
    """Find the ERROR and WARN lines in a log file, with line numbers.

    Use this first to locate problems quickly. Then call read_log if you
    need the lines around them.

    Args:
        file_name: The log file name, for example "order-api.log".

    Returns:
        A dict with "status", "count" and "lines" (each "line_number: text").
    """
    path = _log_path(file_name)
    if path is None:
        return {"status": "error", "error_message": f"No log named {file_name!r}."}
    hits = [
        f"{number}: {line}"
        for number, line in enumerate(path.read_text().splitlines(), start=1)
        if " ERROR " in line or " WARN " in line
    ]
    return {"status": "success", "count": len(hits), "lines": hits}


root_agent = Agent(
    name="root_cause_agent",
    model=Gemini(
        model=MODEL,
        retry_options=types.HttpRetryOptions(attempts=3),
    ),
    instruction=(
        "You are an on-call engineer. When asked about a log, call find_errors "
        "first, then read_log for context. Explain the root cause in plain "
        "words, point to the log lines that prove it, and suggest one fix. "
        "If no file name is given, use order-api.log."
    ),
    tools=[read_log, find_errors],
)

app = App(
    root_agent=root_agent,
    name="app",
)

    What changed

    • Two tools. find_errors returns the ERROR and WARN lines with line numbers. read_log returns the whole file, for context.
    • Docstrings say when to use each tool. "Use this first" and "Use this when you need the full context" steer the model's choice.
    • Tools return a dict with a status. The model can tell a result from an error and react to it.
    • _log_path only allows files inside sample_logs/. The model can't ask for ../.env and read your key. Its name starts with _ and it isn't in tools, so the model never sees it.
    • The instruction tells the agent its job and the order to use the tools in.

    Check that the tools work before you involve the model:

    uv run python -c "from app.agent import find_errors; print(find_errors('order-api.log')['count'])"

    You should see

    The number 15. That's how many ERROR and WARN lines the failing log has.

    Evaluate the agent

    The playground tells you the agent works once. An eval tells you it still works after your next change.

    Back in root-cause-agent, stop the playground with Ctrl+C.

    1. Write the eval cases

    Create tests/eval/datasets/root-cause.json:

    {
  "eval_cases": [
    {
      "eval_case_id": "finds_timeout_root_cause",
      "prompt": {
        "role": "user",
        "parts": [{"text": "What went wrong in order-api.log?"}]
      },
      "reference": {
        "response": {
          "role": "model",
          "parts": [{"text": "Payments fail because v2.4.1 set PAYMENT_TIMEOUT_MS=30 (30ms). The gateway needs about 400ms, so every charge times out and /pay returns 502. Set the timeout back to 3000ms."}]
        }
      }
    },
    {
      "eval_case_id": "healthy_log_has_no_failure",
      "prompt": {
        "role": "user",
        "parts": [{"text": "Is anything broken in order-api-healthy.log?"}]
      },
      "reference": {
        "response": {
          "role": "model",
          "parts": [{"text": "No. Payments succeed. The only warning is a cache miss, which is normal."}]
        }
      }
    },
    {
      "eval_case_id": "missing_file",
      "prompt": {
        "role": "user",
        "parts": [{"text": "Check payments.log for errors."}]
      }
    }
  ]
}

    Each case is a prompt and, optionally, a reference answer. The third case checks that the agent handles a file that doesn't exist.

    2. Pick the metrics

    Replace tests/eval/eval_config.yaml with:

    metrics_to_run:
  - custom_response_quality
  - names_the_timeout

thresholds:
  names_the_timeout: 1.0
  custom_response_quality: 3  # the judge scores 1-5

custom_metrics:
  # Local LLM judge from the template. Uses your GEMINI_API_KEY.
  - name: custom_response_quality
    custom_function_file: response_quality.py
  # Plain Python check. Passes when the answer names the bad setting.
  - name: names_the_timeout
    custom_function: |
      def evaluate(instance):
          prompt = str(instance.get("prompt", ""))
          if "order-api.log" not in prompt or "healthy" in prompt:
              return {"score": 1.0, "explanation": "Not the failing log, skipped."}
          text = str(instance.get("response", "")).lower()
          hit = "payment_timeout_ms" in text or "30ms" in text or "30 ms" in text
          return {"score": 1.0 if hit else 0.0,
                  "explanation": "Names the timeout." if hit else "Misses the timeout."}
    • custom_response_quality is the project's LLM judge. It scores 1 to 5 using your GEMINI_API_KEY.
    • names_the_timeout is plain Python. It checks that the answer names the bad setting. No model call.
    • thresholds make the run fail when a mean score drops below the bar.

    Both run on your laptop. Built-in metrics such as tool_use_quality call the Eval Service in Gemini platform and need a Google Cloud project.

    3. Run it

    agents-cli eval run --dataset tests/eval/datasets/root-cause.json

    It runs the agent on each case, then grades the answers. Open the HTML report in artifacts/grade_results/ to read why each case scored what it did.

    Now break it on purpose. Remove "Use this first to locate problems quickly." from the find_errors docstring, or tell the agent to answer in one word. Run the eval again and compare.

    Two stages, Step 1/2: eval generate and then the grading. The output ends with RESULT: PASS, or RESULT: FAIL (...) with the failing metrics and cases listed above it. A results file appears in artifacts/grade_results/.

    A. Code reviewer

    Reads the changes on a branch and reports bugs, security problems and missing tests. Replace app/agent.py with:

    import subprocess
from pathlib import Path

from google.adk.agents import Agent
from google.adk.apps import App
from google.adk.models import Gemini
from google.genai import types

REPO = Path.cwd()


def get_diff(base: str = "main") -> dict:
    """Get the changes on this branch compared with a base branch.

    Call this first. It returns a unified diff with file names and line
    numbers, which is what you review.

    Args:
        base: The branch to compare against, for example "main".

    Returns:
        A dict with "status" and either "diff" or "error_message".
    """
    result = subprocess.run(
        ["git", "diff", f"{base}...HEAD", "--unified=3"],
        cwd=REPO, capture_output=True, text=True, timeout=30,
    )
    if result.returncode != 0:
        return {"status": "error", "error_message": result.stderr.strip()}
    return {"status": "success", "diff": result.stdout[:200_000]}


def read_file(path: str) -> dict:
    """Read a whole file from the repository, for context around a change.

    Args:
        path: A path relative to the repository root, for example "lib/main.dart".

    Returns:
        A dict with "status" and either "content" or "error_message".
    """
    file = (REPO / path).resolve()
    if REPO.resolve() not in file.parents or not file.is_file():
        return {"status": "error", "error_message": f"No file {path!r} in the repo."}
    return {"status": "success", "content": file.read_text(errors="replace")}


root_agent = Agent(
    name="code_reviewer",
    model=Gemini(model="gemini-3.8-flash", retry_options=types.HttpRetryOptions(attempts=3)),
    instruction=(
        "You review code changes. If the message contains a diff, review it. "

    B. Design reviewer

def _luminance(hex_color: str) -> float:
    rgb = [int(hex_color.lstrip("#")[i:i + 2], 16) / 255 for i in (0, 2, 4)]
    lin = [c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4 for c in rgb]
    return 0.2126 * lin[0] + 0.7152 * lin[1] + 0.0722 * lin[2]


def contrast_ratio(foreground: str, background: str) -> dict:
    """Compute the WCAG contrast ratio between a text color and its background.

    Use this for every text color you can read from the screenshot. Do not
    guess contrast by eye.

    Args:
        foreground: Text color as hex, for example "#777777".
        background: Background color as hex, for example "#FFFFFF".

    Returns:
        A dict with the ratio and whether it passes WCAG AA for normal
        text (4.5:1) and large text (3:1).
    """
    a, b = _luminance(foreground), _luminance(background)
    ratio = (max(a, b) + 0.05) / (min(a, b) + 0.05)
    return {"ratio": round(ratio, 2), "aa_normal_text": ratio >= 4.5, "aa_large_text": ratio >= 3}


def check_touch_target(width_dp: float, height_dp: float) -> dict:
    """Check a tappable element against the 48 x 48 dp minimum touch target.

    Args:
        width_dp: Width of the element in dp.
        height_dp: Height of the element in dp.

    Returns:
        A dict with "passes" and the smallest side.
    """
    passes = width_dp >= 48 and height_dp >= 48
    return {"passes": passes, "smallest_side_dp": min(width_dp, height_dp)}

    import subprocess

def git_log(since: str) -> dict:
    """List the commits since a tag or commit, one per line.

    Call this first to see what changed in the release.

    Args:
        since: A tag or commit, for example "v1.4.0".

    Returns:
        A dict with "status" and either "commits" or "error_message".
    """
    result = subprocess.run(
        ["git", "log", f"{since}..HEAD", "--no-merges", "--pretty=format:%h %s"],
        capture_output=True, text=True, timeout=30,
    )
    if result.returncode != 0:
        return {"status": "error", "error_message": result.stderr.strip()}
    return {"status": "success", "commits": result.stdout.splitlines()}
